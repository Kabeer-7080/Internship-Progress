# Day 45 — API Testing with Postman

## 1. Objective

The objective of Day 45 is to independently test and verify the existing Student Management REST API using the project API test runner, with the same requests documented for Postman. This includes validating successful GET and POST operations, input data validation, duplicate record handling, invalid route detection, unsupported HTTP method handling, HTTP status code compliance, MySQL database persistence, and React frontend integration.

---

## 2. API Endpoints

The Flask backend (`http://127.0.0.1:5000`) exposes the following core endpoints:

* **`GET /api/students`**: Fetches all student records from MySQL database.
* **`POST /api/students`**: Inserts a new student record into MySQL database with strict validation and unique email constraints.

## 4. Sample JSON Requests

### Valid Create Request (`POST /api/students`)

```json
{
  "name": "Neha Gupta",
  "email": "neha.gupta@example.com",
  "course": "Cyber Security"
}
```

**Response shape (`201 Created`; the `id` is generated by MySQL):**
```json
{
  "success": true,
  "message": "Student added successfully",
  "student": {
    "id": 16,
    "name": "Neha Gupta",
    "email": "neha.gupta@example.com",
    "course": "Cyber Security"
  }
}
```

### Invalid Request — Empty Field (`POST /api/students`)

```json
{
  "name": "",
  "email": "test@example.com",
  "course": "IT"
}
```

**Response (`400 Bad Request`):**
```json
{
  "success": false,
  "message": "Name, email, and course are required"
}
```

### Duplicate Email Request (`POST /api/students`)

```json
{
  "name": "Another Student",
  "email": "arun@example.com",
  "course": "IT"
}
```

**Response (`409 Conflict`):**
```json
{
  "success": false,
  "message": "Email already exists"
}
```

## 5. HTTP Status Codes

The API enforces standardized RESTful HTTP status codes:

* **`200 OK`**: Successful `GET` request retrieving students.
* **`201 Created`**: Student successfully inserted into MySQL.
* **`400 Bad Request`**: Client sent invalid or incomplete input (missing name, email, course, empty payload, or missing body).
* **`404 Not Found`**: Requested endpoint does not exist (e.g., `/api/student`).
* **`405 Method Not Allowed`**: HTTP method is not supported (e.g., `DELETE` on `/api/students`).
* **`409 Conflict`**: Email already exists in MySQL (triggers `UNIQUE` constraint).
* **`500 Internal Server Error`**: Unexpected database or server error.
